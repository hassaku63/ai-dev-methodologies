# adopt

今のリポジトリを、ai-dev-methodologies の規約（`AGENTS.md` を正典にする、検査を `make check` に集める、Issue と PR で作業を回す、文書を現在の状態に保つ）に合わせる。新規のリポジトリにも、既存のリポジトリにも使う。

ファイルを置くのはスクリプト、判断が要るところはこの手順で行う。スクリプトは、このスキルのディレクトリの `adopt.sh`。

## 手順

1. **調べる。** リポジトリを読み、次を把握する。分からないことだけを所有者に尋ねる。
   - 何のリポジトリか。アプリケーション、IaC（CDK、Terraform）、運用・管理（インフラの調査と記録）のどれに当たるか。複数に当たってよい。
   - すでにある指示書（`AGENTS.md`、`CLAUDE.md`、`.cursor/rules` など）、検査（`Makefile`、CI、lint の設定）、文書。
   - main に当たるブランチの名前。
2. **置かれるものを見せる。** `bash <このスキルのディレクトリ>/adopt.sh --dry-run <リポジトリの最上位>` を走らせ、結果を所有者に示す。`exists` と `kept` は、すでにあって触らないファイル。
3. **置く。** 作業用のブランチで、`--dry-run` を外して走らせる。
4. **すでにあったファイルを合わせる。** `exists` と `kept` の行ごとに、今あるファイルを読み、規約に足りないものだけを足す。置き換えない。
   - `Makefile`: `check` のターゲットがあり、`docs-check` を呼ぶ。今ある検査（lint、テスト、ビルド）も `check` から呼ぶ。`Makefile` を使わない方針なら、`make check` に当たる 1 つのコマンドを所有者と決め、`AGENTS.md` に書く。
   - `AGENTS.md`: 今ある内容を残し、雛形（スキルのディレクトリの `assets/owned/AGENTS.md.tmpl`）の節のうち、無いものを足す。`CLAUDE.md` に規則が書いてあれば `AGENTS.md` に移し、`CLAUDE.md` は `@AGENTS.md` と Claude Code に固有の補足だけにする。
   - `.claude/settings.json`: 今ある設定を残し、`extraKnownMarketplaces` と `enabledPlugins` の項目を足す。
   - `.github/workflows/ci.yml`: 今ある CI に、`make check` を呼ぶ必須のジョブがあるようにする。
   - `docs/README.md`: `docs/` の文書を全部、Markdown のリンクで載せる。
   - `.gitignore`: `.claude/settings.local.json` を足す。
5. **埋める。** 作ったファイルの「（導入先で書く: …）」を、リポジトリを読んで分かる範囲で埋める。推測で埋めない。読んでも分からないものは、所有者に尋ねるか、そのまま残して最後に一覧にする。
   - 今ある検査を `docs/dev/harness.md` に 1 行ずつ足す。
   - CI の雛形の「Set up the tools」に、検査が要る道具の導入を書く。
6. **任せる範囲を決める。** 所有者に、エージェントに任せる範囲を尋ね、`AGENTS.md` のガードレールに書く。調べて報告するだけ、コードを変えて PR を作る、インフラの変更を計画する（plan や diff まで）、開発環境に反映する、のどれか。本番環境への反映は、どれを選んでも人間が行う。
7. **このリポジトリに固有の知識を書いてもらう。** 所有者に、次を `docs/` に自分で書くよう促す。書く場所と見出しの案を示し、中身は所有者が決める。エージェントは、会話で聞いた内容を勝手に文書にしない。
   - 組織やチームの規則のうち、このリポジトリの作業に関わるもの。
   - 関係する文書やほかのリポジトリの場所。
   - 用語、環境の名前、連絡先。
   これらは導入先のリポジトリにだけ置く。ai-dev-methodologies には送らない。
8. **ラベルを用意する。** `observation`、`proposal`、`needs-decision`、`ready`、`priority:high` のうち無いものを、所有者に確かめてから作る。
9. **確かめる。** `make check` を通す。通らなければ、検査を弱めずに直す。
10. **報告する。** 置いたファイル、合わせたファイル、残した「（導入先で書く: …）」、所有者が決めること、を一覧にする。PR を開くかどうかは所有者に確かめる。

## 新しい版に合わせる

導入済みのリポジトリでは、手順 2 から行う。`updated` は新しい版に置き換えたファイル。`kept` は手で変えてあったので置き換えなかったファイルで、スキルのディレクトリの `assets/managed/` の同じパスとの差分を読み、取り込むかどうかを所有者に示す。

## 守ること

- 今ある規則や検査を消さない。食い違いは、所有者に示して決めてもらう。
- 検査を通すために、文書や検査を弱めない。
- `.agents/methodology.lock` を手で書き換えない。
