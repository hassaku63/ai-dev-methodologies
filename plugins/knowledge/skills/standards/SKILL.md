# standards

ファイル形式・記法・プロトコル・設定ファイルの書き方を決める前に、業界標準の一次情報に当たる。

| 置き場所 | 中身 |
| --- | --- |
| この plugin の `catalog/standards/` | 標準の項目（発行元、何を決めているか、一次情報、状態、当たるべき場面、確認）。どのリポジトリでも同じ |
| 作業中のリポジトリの `./docs/knowledge/standards.md` | 対応表。このリポジトリで使う項目の ID と、このリポジトリとの接点（関係するファイル、ADR、検査。標準の勧めとの食い違い） |

## 使い方

1. 決めようとしていることを 1 行で言う（例: 「Dockerfile で `COPY --exclude` を使う」）。
2. 対応表と目録で、当たる項目を探す。
3. 見つかったら、仕様の中身は推測せず、その項目の一次情報を開いて確かめる。開けなければ、開けなかったことを PR か Issue に書き、推測で書かない。
4. 見直しの期限（確認日 + 間隔）を過ぎた項目を根拠に使うときは、先に一次情報を開き直す。
5. リポジトリの書き方が標準の勧めと食い違うときは、対応表の「接点」に食い違いとして書く案を示す。直すかどうかは別の Issue にする。
6. 見つからなければ、そう書いて進める。足すべき標準だと思ったら、観察の Issue にする。

## プラクティスとの分担

| 索引 | 引く場面 |
| --- | --- |
| プラクティス（スキル `practices`） | 設計・実装・レビューで、テストや抽象や境界を決めるとき |
| 業界標準（このスキル） | ファイル形式・記法・プロトコル・設定ファイルの書き方を決めるとき |
