# inventory

AWS の構成を読み取って、1 つの記録にまとめる。目的は、所有者が今の構成を把握し、見直すところを決められること。エージェントは読み取りと記録だけを行い、環境を変えない。

取得はスクリプト（このスキルのディレクトリの `collect.sh`）、記録を作るのもスクリプト（`summarize_inventory.py`）。同じ取得結果からは同じ記録ができる。

## 前提

| もの | 場所 |
| --- | --- |
| 取得したままの出力 | `ops/raw/inventory/<日付>/<リージョン>/`（コミットしない） |
| 棚卸しの記録 | `ops/inventory.md`。毎回、上書きする。前回との差は git の差分で見る |
| アプリケーションの単位の定義（任意） | `ops/apps.json` |

## 手順

1. **誰として読むかを確かめる。** `aws sts get-caller-identity` の結果（アカウントとロール）を所有者に示す。読み取り専用の認証情報でなければ、止めて所有者に伝える。
2. **対象のリージョンを決める。** `ops/README.md` に書いてあればそれ。なければ所有者に尋ねる。
3. **取得する。**
   ```bash
   bash <このスキルのディレクトリ>/collect.sh ops/raw/inventory/<日付> <リージョン> [<リージョン> ...]
   ```
   `failed` の行があれば、何が取れなかったか（権限、サービスが無効）を所有者に伝える。記録にも載る。
4. **記録を作る。**
   ```bash
   python3 <このスキルのディレクトリ>/summarize_inventory.py --raw ops/raw/inventory/<日付> \
     --apps ops/apps.json --account <アカウント ID> --date <日付> --out ops/inventory.md
   ```
   `ops/apps.json` が空か無ければ、`--apps` を外す。
5. **前回との差を見る。** `git diff -- ops/inventory.md` で、増えたもの・消えたもの・変わったものを挙げる。
6. **読み解きを足す。** 記録そのものは書き換えない。会話で、次を短く伝える。
   - 「外から届くもの」のうち、意図を確かめた方がよいもの（管理用のポートを `0.0.0.0/0` に開けた規則、外向きのサブネットにあるパブリック IP のインスタンスなど）と、その理由。
   - どのアプリケーションにも当たらないリソース。定義に足すか、不要なものかを所有者が決める。
   - 前回との差で、説明のつかないもの。
   - 事実として確かめたことと、推測を分ける。推測には、確かめ方を書く。
7. **アクションにする。** 所有者が対応すると決めたものを、`observation` か `proposal` の Issue にする案を示す。Issue を作るのは、所有者が確かめてから。

## 記録にないものを調べるとき

記録が扱うのは、ネットワーク、インスタンス、ECS、Lambda、ロードバランサー、RDS。ほかのもの（IAM、S3、CloudFront、Route 53 など）を調べるときは、`describe-*`、`list-*`、`get-*` の読み取りで個別に取り、出力を `ops/raw/` に置いて、分かったことを会話で伝える。記録に足す価値が続くものは、`observation` の Issue で、スクリプトに足す提案にする。

## 守ること

- AWS を変える操作をしない。変える案は、所有者への提案として書く。
- 記録の中身（アカウント ID、リソースの名前、IP アドレス）を、このリポジトリの外に送らない。
- 数や状態を、記録と違う値で伝えない。値は記録から引く。
