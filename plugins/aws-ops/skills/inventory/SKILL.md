# inventory

AWS の構成を読み取って、1 つの記録にまとめる。目的は、所有者が今の構成を把握し、見直すところを決められること。エージェントは読み取りと記録だけを行い、環境を変えない。

取得はスクリプト（このスキルのディレクトリの `collect.sh`）、記録を作るのもスクリプト（`summarize_inventory.py`）。同じ取得結果からは同じ記録ができる。

スクリプトが詳しい表にするのは、決まった種類だけ。それ以外の種類は、種類を問わない発見（AWS Config、タグ付けの API、Resource Explorer）で数と ARN を挙げ、中身はエージェントが個別に調べて補う。

## 前提

| もの | 場所 |
| --- | --- |
| 取得したままの出力 | `ops/raw/inventory/<日付>/<リージョン>/`（コミットしない） |
| 棚卸しの記録 | `ops/inventory.md`。スクリプトが作り、毎回、上書きする。前回との差は git の差分で見る |
| 表の無い種類の補足 | `ops/inventory-notes.md`。エージェントが書き、毎回、書き直す |
| アプリケーションの単位の定義（任意） | `ops/apps.json` |

## 手順

1. **誰として読むかを確かめる。** `aws sts get-caller-identity` の結果（アカウントとロール）を所有者に示す。読み取り専用の認証情報でなければ、止めて所有者に伝える。
2. **対象のリージョンを決める。** `ops/README.md` に書いてあればそれ。なければ所有者に尋ねる。
3. **取得する。**
   ```bash
   bash <このスキルのディレクトリ>/collect.sh ops/raw/inventory/<日付> <リージョン> [<リージョン> ...]
   ```
   `failed` の行があれば、何が取れなかったか（権限、サービスが無効）を所有者に伝える。記録にも載る。
4. **記録を作る。**
   ```bash
   python3 <このスキルのディレクトリ>/summarize_inventory.py --raw ops/raw/inventory/<日付> \
     --apps ops/apps.json --account <アカウント ID> --date <日付> --out ops/inventory.md
   ```
   `ops/apps.json` が空か無ければ、`--apps` を外す。
5. **表の無い種類を拾う。** 記録の「すべての種類」の節は、種類を問わずに見つけたリソースを数える。「詳しい表」が「なし」の種類を、1 つも飛ばさずに見る。
   - 種類ごとに、構成の把握に要るかを判断する。要るもの（データを持つもの、外から届くもの、費用のかかるもの、アプリケーションの動きを決めるもの）は、`describe-*`、`list-*`、`get-*` の読み取りで個別に取り、出力を `ops/raw/inventory/<日付>/` に置く。
   - 分かったことを `ops/inventory-notes.md` に書く。種類ごとに、何があるか、どのアプリケーションのものか、気になる点。詳しく見なかった種類も、見なかった理由と一緒に 1 行で載せる。毎回、書き直す。
   - 「種類を問わない発見は、どの出どころからも取れなかった」と出ていたら、記録は決まった種類しか含まない。所有者にそう伝え、AWS Config か Resource Explorer を使えるようにするか、使っているサービスを所有者に尋ねて個別に調べる。
   - 出どころが取れていても、漏れはある。所有者が知っているのに記録に無いサービスがないかを、尋ねる。
6. **前回との差を見る。** `git diff -- ops/inventory.md ops/inventory-notes.md` で、増えたもの・消えたもの・変わったものを挙げる。
7. **読み解きを足す。** 記録そのものは書き換えない。会話で、次を短く伝える。
   - 「外から届くもの」のうち、意図を確かめた方がよいもの（管理用のポートを `0.0.0.0/0` に開けた規則、外向きのサブネットにあるパブリック IP のインスタンスなど）と、その理由。
   - どのアプリケーションにも当たらないリソース。定義に足すか、不要なものかを所有者が決める。
   - 前回との差で、説明のつかないもの。
   - 事実として確かめたことと、推測を分ける。推測には、確かめ方を書く。
8. **アクションにする。** 所有者が対応すると決めたものを、`observation` か `proposal` の Issue にする案を示す。Issue を作るのは、所有者が確かめてから。繰り返し詳しく調べる種類は、スクリプトの表に足す提案を、ai-dev-methodologies の `observation` の Issue にする案として示す。

## 守ること

- AWS を変える操作をしない。変える案は、所有者への提案として書く。
- 記録の中身（アカウント ID、リソースの名前、IP アドレス）を、このリポジトリの外に送らない。
- 数や状態を、記録と違う値で伝えない。値は記録から引く。
