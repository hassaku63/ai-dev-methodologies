# 0003. 配るものを 3 種類に分ける

- 日付: 2026-11-15
- 状態: Accepted

## 文脈

`hassaku63/middy` と `hassaku63/chord-rambler` のあいだで、手作業のコピーが起きている。標準の索引（chord-rambler の ADR-0015 が middy から 3 項目を移した）、検査のスクリプト、`.claude/settings.json`、Issue と PR のテンプレート。コピーは、それぞれのリポジトリで別々に古くなる。

一方で、すべてを plugin にはできない。CI が呼ぶスクリプトやワークフローは、リポジトリの中に実在が要る。`AGENTS.md` や索引の項目は、導入先ごとに中身が違う。

## 決定

配るものを、次の 3 種類に分ける。

1. **手順。** どの導入先でも同じもの。plugin で配り、更新が届く。
2. **リポジトリに実在が要るもの。** 導入のときにコピーし、導入した版を導入先に記録する。
3. **導入先が所有するもの。** 雛形だけを作り、中身は導入先で書く。更新で上書きしない。

plugin の手順が前提にする導入先のパスとコマンドは、規約としてこのリポジトリで定義する。

## 検討した選択肢

- **すべてコピーする**（Jacky Ma の方式に近い）: 導入先が自己完結する。手順の更新が届きにくい。
- **すべて plugin にする**: 更新が確実に届く。CI から呼べず、導入先ごとの違いを持てない。

## 結果

- 部品を作るたびに、どの種類かを決める必要がある。迷うものは、導入先ごとに違うかどうかで分ける。
- 2 のコピーの更新の方式は、まだ決めていない（`docs/roadmap.md`）。
- 再検討の条件: 規約に合わせるための導入先の手直しが、導入のたびに大きいとき。
