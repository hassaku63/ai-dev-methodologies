# 0001. 決定を ADR に記録する

- 日付: 2026-11-15
- 状態: Accepted

## 文脈

このリポジトリの作業は、セッションをまたいで続く。エージェントは前のセッションの会話を覚えていない。なぜその形にしたかが残っていないと、同じ検討を繰り返すか、決定を知らずに覆す。

## 決定

設計判断は `docs/architecture/adr/` に 1 枚ずつ記録する。文脈、決定、検討した選択肢、結果を書く。ADR は決定の時点の記録で、現在の状態はほかの文書に書く。

## 検討した選択肢

- **コミットメッセージだけに残す**: 手間がない。採らなかった案と理由が残らず、探しにくい。
- **1 つの設計文書に書き足す**: 1 箇所で読める。経緯と現在の状態が混ざる。

## 結果

決定のたびに 1 枚を書く手間がかかる。出どころのリポジトリ（`hassaku63/chord-rambler`、`hassaku63/middy`）と同じ形なので、導入先に配る雛形にそのまま使える。
