# 0005. 任せる範囲を段階で選び、本番への反映は人間が行う

- 日付: 2026-11-15
- 状態: Accepted

## 文脈

所有者は、安全に、少しずつエージェントに作業を任せたい。導入先には AWS のインフラを扱うものがあり、誤った操作の影響が大きい。高頻度の開発は要らない。

## 決定

1. 導入のときに、導入先ごとに次の段階から 1 つを選ぶ。

   | 段階 | エージェントに許すこと |
   | --- | --- |
   | L0 調べて報告 | AWS の読み取りと、記録の作成 |
   | L1 コードを変える | ブランチで変更して PR を作る。インフラへの反映はしない |
   | L2 変更を計画する | `terraform plan` や `cdk diff` の実行と、結果の要約 |
   | L3 開発環境に反映する | 開発環境に限った反映 |

2. 本番環境への反映は、どの段階でも人間が行う。
3. 安全性は、1 つの仕組みに頼らず重ねる。AWS の権限（エージェントには読み取り専用の認証情報）、Claude Code の権限の設定、フック、CI の検査。最後の防壁は AWS の権限に置く。
4. エージェントの失敗は、注意書きを足す前に、検査、フックと権限の設定の順で固定できないかを考える。

## 検討した選択肢

- **段階を置かず、導入先ごとに権限を手で書く**: 柔軟。導入のたびに考え直すことになり、抜けが出やすい。
- **指示書の注意書きだけで制限する**: 仕組みが要らない。守られる保証がない。

## 結果

- 運用・管理のリポジトリは L0 から始められる。失敗しても環境を変えない。
- 段階ごとの権限の設定とフックを、部品として用意する必要がある。
- 再検討の条件: 段階のあいだに置き場所の決まらない操作が繰り返し出てきたとき。
