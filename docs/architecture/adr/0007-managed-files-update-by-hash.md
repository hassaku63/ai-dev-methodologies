# 0007. コピーしたファイルは、ハッシュで手直しを見分けて更新する

- 日付: 2026-11-15
- 状態: Accepted（所有者は、エージェントの推奨で進めるよう指示した）

## 文脈

導入先にコピーしたファイル（検査のスクリプト、Issue のテンプレートなど。ADR-0003）は、このリポジトリで直したら導入先にも届けたい。導入先では、そのリポジトリの都合で手直しされていることがある。上書きすると手直しが消え、何もしなければ古いまま残る。

## 決定

1. 導入のとき、コピーしたファイルごとの SHA-256 を、導入先の `.agents/methodology.lock` に記録する。
2. 新しい版に合わせるとき、導入先のファイルがロックのハッシュと同じなら、新しい版で置き換える。違っていれば、手で変えたものとして残し、報告する。
3. 残したファイルは、スキルが新しい版との差分を読み、取り込むかどうかを所有者に示す。機械では合わせない。
4. 導入の前からあって中身が違うファイルも、同じく残す。ロックには `local` と記録する。

## 検討した選択肢

- **常に上書きする**: 仕組みが最も小さい。導入先の手直しを黙って消す。
- **3 方向のマージをする**: 手直しと更新の両方を残せる。導入したときの版の中身が要り、競合の解決が結局人手になる。コピーするファイルは少なく、手直しはまれなので釣り合わない。
- **版の番号だけを記録する**: 何が導入されたかは分かる。手直しの有無が分からない。

## 結果

- 手直ししたファイルには、所有者が取り込むまで更新が届かない。手直しが要るものは、コピーするファイルではなく、導入先が所有するファイルに出すべきという合図になる。
- ロックのファイルを手で書き換えると、見分けが壊れる。
- 再検討の条件: 残したファイルの報告が、新しい版に合わせるたびに出るようになったとき。
