# 0008. 導入先が守る規約を 1 つの文書に持ち、このリポジトリ自身にも導入する

- 日付: 2026-11-15
- 状態: Accepted

## 文脈

plugin の手順は、導入先に `docs/dev/workflow.md` や `make check` があることを前提にする（ADR-0003）。前提が手順の文のあちこちに散ると、何を守れば手順が働くのかが分からず、手順を変えたときに導入先が壊れても気づけない。

規約の形は、出どころのリポジトリ（`hassaku63/chord-rambler`）で動いているものがある。

## 決定

1. 導入先が守る規約（パス、コマンド、ラベル、ブランチの名前）を `docs/contract.md` に持つ。手順が新しい前提を持つときは、同じ変更でここに足す。
2. 規約の形は、`hassaku63/chord-rambler` のものをそのまま使う。新しい名前を作らない。
3. このリポジトリ自身に `core` を導入し、同じ規約で作業する。
4. 空のリポジトリへの導入を、`make check` の中で確かめる（`scripts/test-adopt.sh`）。

## 検討した選択肢

- **規約を設定のファイルで変えられるようにする**（文書の場所などを導入先ごとに選ぶ）: 既存のリポジトリに合わせやすい。手順がすべて間接参照になり、確かめる組み合わせが増える。使う人は 1 人なので、導入先を規約に合わせる方が安い。
- **`Makefile` を前提にしない**: `make` のない環境でも使える。検査を 1 つのコマンドに集める形が、導入先ごとに違ってしまう。

## 結果

- 既存のリポジトリは、導入のときに規約のパスへ文書を寄せる必要がある。
- このリポジトリで規約が使いにくければ、導入先より先に気づける。
- 再検討の条件: 規約に合わせられない導入先が出てきたとき。
