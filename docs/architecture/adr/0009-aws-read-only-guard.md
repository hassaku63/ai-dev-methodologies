# 0009. 運用・管理のリポジトリでは、フックで AWS の操作を読み取りに限る

- 日付: 2026-11-15
- 状態: Accepted

## 文脈

運用・管理のリポジトリでは、エージェントが `aws` の CLI でインフラの構成や Finding を取得して記録する。任せる範囲は「調べて報告」（ADR-0005 の L0）で、環境を変える操作はさせない。

最後の防壁は、エージェントが使う AWS の認証情報を読み取り専用にすること（ADR-0005）。ただし、認証情報の設定は導入先の所有者が行うもので、誤って強い権限のプロファイルで動かすことがありうる。読み取り専用の権限でも、秘密情報の値やデータの中身は読めることがある。

Claude Code の権限の設定は、コマンドの文字列の前方一致で書く。`aws` の CLI はグローバルなオプションが操作の前に来るので、前方一致では読み取りだけを通す規則を書ききれない。

## 決定

1. plugin `aws-ops` が、Bash の実行の前に走るフックを持つ。コマンドの中の `aws` の呼び出しをすべて見る。
2. **通すものを並べる。** 操作の名前が読み取りの動詞（`describe`、`get`、`list` など）で始まるものだけを通す。それ以外は止める。新しいサービスの書き込みの操作は、一覧を直さなくても止まる。
3. **読み取りでも、秘密情報・認証情報・保存されたデータを返すものは止める。** `secretsmanager get-secret-value`、`ssm get-parameter --with-decryption`、`s3api get-object`、`sts`（`get-caller-identity` を除く）など。
4. **読み取りかどうか分からないものは、所有者に尋ねる。** 操作のない呼び出し、解析できないコマンド、サインイン。
5. 止めたときは、別の方法を探さず、そのコマンドを所有者への提案として報告に書くよう、エージェントに伝える。
6. フックは安全網で、防壁ではない。変数を経由した呼び出しなどは見つけられない。導入の手順で、読み取り専用の認証情報を使うことを所有者に求める。

## 検討した選択肢

- **権限の設定の `deny` に書き込みの操作を並べる**: 仕組みが要らない。止めるものを並べる形になり、並べ忘れた操作が通る。グローバルなオプションを前に置くと一致しない。
- **`aws` をすべて所有者の確認にする**: 確実。調査は読み取りを何十回も行うので、確認が多すぎて使われなくなる。
- **フックを置かず、認証情報だけに頼る**: 最も単純で、防壁としては正しい。誤ったプロファイルで動かしたときと、秘密情報の読み取りを防げない。

## 結果

- 読み取りの動詞に当たらない読み取り（`logs start-query`、`cloudformation detect-stack-drift` など）は止まる。要るものは、一覧に足すか、所有者が自分で走らせる。
- フックは Python 3 を要する。
- `aws` という語を引数に含むだけのコマンドが、尋ねる扱いになることがある。
- 再検討の条件: 止まった読み取りの報告が続くとき。フックをすり抜けた書き込みがあったとき。
