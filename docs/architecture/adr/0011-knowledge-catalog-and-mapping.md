# 0011. 知識の索引は、中央の目録と、リポジトリの対応表に分ける

- 日付: 2026-11-15
- 状態: Accepted（所有者の判断は #13）

## 文脈

`hassaku63/chord-rambler` は、開発のプラクティスの索引と業界標準の索引を持つ。項目は、出どころと確認日を持ち、検査と定期の報告で鮮度を保つ。ソフトウェア開発一般と、いくつかの技術の知見は、ほかのリポジトリにも使える。

- chord-rambler の ADR-0015 は、`hassaku63/middy` の索引から 3 項目を手で移し、「確認と接点はそれぞれのリポジトリで持つ」と決めた。写しは、それぞれで古くなる（ADR-0003 と同じ問題）。
- 項目の欄は、出どころに付くもの（出どころ、何を言っているか、確からしさ、判断の問い、対象、確認）と、リポジトリに付くもの（そのリポジトリでの場面、プロジェクトの立場、標準との接点）に分かれる。

## 決定

1. 出どころに付く欄を、plugin `knowledge` の目録（`plugins/knowledge/catalog/`）に持つ。技術ごとの束に分ける。項目は変えない ID を持つ。
2. 導入先は、対応表（`<導入先>/docs/knowledge/practices.md`、`<導入先>/docs/knowledge/standards.md`）だけを持つ。使う項目の ID、そのリポジトリでの場面、プロジェクトの立場、標準との接点。そのリポジトリだけの項目も、目録と同じ形で対応表に持てる。
3. 目録の出どころの鮮度（開き直し）は、このリポジトリで見る。直した目録は、plugin の更新で導入先に届く。
4. 目録の 1 項目を直すと、すべての導入先に届く。ほかの配る部品と同じく、所有者の OK を待つ（`docs/dev/workflow.md` の「マージ」）。

## 検討した選択肢

- **種の項目をコピーし、導入先が所有する**: chord-rambler と同じ形で、導入先が自己完結する。写しがそれぞれで古くなり、出どころの開き直しをリポジトリごとに繰り返す。
- **全部を plugin に置く**: 最も単純。そのリポジトリでの場面と立場を持てず、対象の版を導入先の依存と照らせない。
- **取り込まない**: 維持するものが増えない。新しいリポジトリのたびに、索引を一から作るか、手でコピーする。

## 結果

- 出どころの確認が 1 回で済む。新しいリポジトリに入れるのが速い。
- 項目の書き方が、chord-rambler の形と変わる。chord-rambler と middy を目録に移すかは、別に決める（#13）。
- 目録の項目の当たるべき場面と判断の問いは、特定のリポジトリの例を書けない。具体的な場面は、対応表で補う。
- 再検討の条件: 対応表の「このリポジトリでの場面」が、ほとんどの項目で目録と違うものになるとき（目録の場面が一般的すぎる）。
